## 如何追加下一代

1. 运行一代：

   ```bash
   python -X utf8 evolution.py --generations 1 --yes --no-color
   ```

2. 从 `data/evolution/logs/gen-0NN.result.json` 读取：结果、测试数、评测分数、
   commit、tag、token 用量与调用次数；同时查看 `diagnosis`（失败模式与组件
   归因）和 `experience`（本代写入经验库的条目）。
3. 在下面的“逐代索引”表末尾加一行。
4. 在“逐代记录”末尾按模板加一节；拒绝的代数写清拒绝原因和基线是否变化。
5. 更新本文件顶部的“当前状态”。
6. 不要重写历史记录；如果发现旧记录有误，追加一条更正说明。

进化主线可以分成四段：

1. **工具可信**：命令失败要报错、CRLF/LF 精确匹配、读取越界要提示。
2. **循环收敛**：落盘后重置只读计数，压缩摘要保留进度事实。
3. **读取效率**：从“重复读取提醒”逐步升级到“重叠区间硬跳过 + 按会话隔离”。
4. **Harness 自身**：自动选目标、过滤不可执行建议、去重、防止无改动空转。

## Harness 六段闭环

第 20 代之后补强了 Harness 自身，使自进化从“自动选目标”升级为完整闭环：

| 环节 | 现在的实现 |
|---|---|
| 1. 可编辑组件 | [agent.py](../agent.py)、[tools.py](../tools.py)、[prompts.py](../prompts.py)、[memory.py](../memory.py)、[sessions.py](../sessions.py)、[llm.py](../llm.py)、[server.py](../server.py)、[web/](../web/)、[docs/](.)、[harness.py](../harness.py) 及新建 Python 模块 |
| 2. 轨迹采集 | 每代保留完整 `.trace.jsonl`，并把轨迹压成指标写入 `result.json` 与 ledger：`actions`、`read_calls`、`write_calls`、`duplicate_actions`、`duplicate_reads`、`skipped_reads`、`tool_errors`、`zero_tool` |
| 3. 弱点诊断 | `_diagnose_generation()` 识别 `no_change`、`claimed_without_edit`、`zero_tool_final`、`blind_read_loop`、`duplicate_actions`、`test_failure`、`eval_regression`、`frozen_boundary` 等失败模式，并归因到 `prompts` / `tools` / `agent_loop` / `memory` / `sessions_web` / `harness` |
| 4. 修改提案 | `_score_proposal()` 按“命中历史失败模式、覆盖未验证组件、包含具体文件或符号、与最近目标差异”给候选建议打分；`_auto_objective()` 只从去重且可行的提案中取最高分，并把 `proposals` 写进 ledger。复盘没有可执行建议时，`_diagnostic_proposals()` 会按失败模式生成兜底提案 |
| 5. 验证筛选 | 沿用基线/候选测试、安全检查、冻结边界、改动预算、`py_compile`、评测分数门槛；只有净正向改动会被提交和打 tag |
| 6. 经验沉淀 | `_experience_entry()` 把目标、组件、失败模式、改动摘要、验证结果、适用条件写入 `data/evolution/experience.jsonl`；`_experience_summary()` 把已验证/已否决经验和失败模式统计注入下一代提示 |

对应闭环：跑任务 → 留轨迹 → 找毛病 → 提改法 → 验效果 → 存经验。
每代 `result.json` 现在会额外包含 `diagnosis` 和 `experience` 字段。

## 日志位置

完整过程日志都在 `data/evolution/`（该目录被 `.gitignore` 忽略）：

- `logs/gen-0NN.log`：逐轮 Thought / Action / Observation 与控制台输出
- `logs/gen-0NN.trace.jsonl`：结构化轨迹（第 2 代起）
- `logs/gen-0NN.result.json`：该代决策、测试、评测、commit、用量
- `ledger.jsonl`：所有代的目标、来源、决策、用量、轨迹指标与诊断索引
- `experience.jsonl`：验证通过/否决的经验条目，含组件、失败模式与适用条件
- `genNN-console.log`：每一代单独的控制台日志
